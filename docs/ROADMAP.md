# 분리수거 AI – 출시 & 수익화 로드맵

> 작성일: 2026-10-17 · 현재 상태: MVP 완성 (사진 판별 / 가이드 / 기록 / API 키 설정, CI로 APK 빌드)

## 0. 먼저 솔직하게: 이 앱의 구조적 특징

- **사용 빈도가 낮다.** "이거 어디 버리지?"는 일주일에 몇 번 생기는 질문이라 자연 리텐션이 낮다.
  → 수익화는 광고 노출량에 기대기 어렵고, **다시 열게 만드는 장치**(배출 요일 알림, 챌린지)가 필수.
- **판별 1회마다 비용이 든다.** Gemini 호출이므로 무제한 무료는 위험. 무료 횟수 제한 + 유료/보상형 광고로 해소.
- **API 키가 앱 안에 있으면 안 된다.** 지금 MVP는 사용자가 직접 키를 넣는 구조. 공개 배포 전 반드시 서버(Firebase) 뒤로 숨겨야 한다. 키가 새면 내 카드로 청구된다.
- **B2B/B2G가 진짜 매출일 가능성이 높다.** 한국에서 이 카테고리는 개인 결제보다 아파트 단지·학교·지자체 환경교육 예산이 더 현실적인 돈이다. 개인 앱은 "실제 사용자 수"를 증명하는 포트폴리오 역할을 한다.

## 1. 수익 모델 (3단 구조)

| 층 | 내용 | 비고 |
|---|---|---|
| 무료 | 하루 판별 5회, 가이드 무제한, 하단 배너 광고 | 광고 보면 판별 +3회 (보상형) |
| 프리미엄 | 무제한 판별, 광고 제거, 배출 요일 알림, 기록 무제한 | 월 1,900원 / 연 9,900원 (7일 무료 체험) |
| 기관 | 단지·학교·지자체용 라이선스: 브랜딩, 통계 대시보드, 교육 콘텐츠 | 출시 후 사용자 수를 근거로 제안 |

광고는 **AdMob** (배너 + 결과 화면 전면 + 보상형), 구독은 **RevenueCat(purchases_flutter)** 로 Android/iOS 한 번에 처리.

## 2. 단계별 계획

### Phase 1 – 출시 기반 (1~2주)
목표: "남한테 배포해도 안전한 앱"

- [ ] Firebase 프로젝트 생성 (Analytics, Crashlytics, Auth 익명 로그인, App Check)
- [ ] **Firebase AI Logic(`firebase_ai`)로 Gemini 호출 전환** → 앱에서 API 키 제거, App Check로 남용 차단
- [ ] 사용자별 일일 판별 횟수 제한 (Firestore 또는 로컬 + 서버 검증)
- [ ] "결과가 틀렸어요" 피드백 버튼 → Firestore 저장 (프롬프트 개선 데이터)
- [ ] 앱 아이콘, 스플래시, 앱 이름 확정, 온보딩 3장 (왜 필요한지 / 어떻게 쓰는지 / 권한)
- [ ] 개인정보처리방침 + 이용약관 페이지 (사진이 Google 서버로 전송됨을 명시) – 웹 호스팅(GitHub Pages)
- [ ] 결과 화면 공유 카드 (이미지로 저장/공유 → 바이럴 유입)

### Phase 2 – 리텐션 & 수익화 (2~3주)
목표: "다시 열게 만들고, 돈이 들어오는 구조"

- [ ] **배출 요일 알림**: 우리 동네 재활용 배출 요일 설정 → 전날 저녁 푸시 ("내일은 플라스틱·비닐 버리는 날이에요"). 리텐션의 핵심 기능
- [ ] 지자체별 배출 정보: 공공데이터포털 "생활쓰레기 배출 정보" 활용, 없으면 사용자가 직접 설정
- [ ] 대형폐기물 신고 바로가기 (지자체별 링크), 폐가전 무상수거 연결
- [ ] 스트릭/포인트: 판별·가이드 열람으로 포인트 적립, 주간 챌린지 ("이번 주 10개 분리배출")
- [ ] AdMob 배너 + 보상형 광고 ("광고 보고 3회 더")
- [ ] RevenueCat 구독 연동, 페이월 화면, 7일 체험
- [ ] 홈 위젯 (이번 주 배출 요일) – Android 먼저

### Phase 3 – 스토어 출시 (1~2주)
목표: Google Play 프로덕션 등록

- [ ] Google Play 개발자 계정 ($25, 1회). **개인 계정은 비공개 테스트 12명 × 14일 통과해야 프로덕션 신청 가능** → 테스터 미리 모아두기
- [ ] 릴리스 키스토어 생성, GitHub Secrets에 저장, CI에서 서명된 AAB 빌드
- [ ] 스토어 등록: 스크린샷 6장, 짧은 설명(80자), 긴 설명, 데이터 보안 양식(사진 전송 명시), 광고 포함 표시
- [ ] 내부 테스트 → 비공개 테스트(14일) → 프로덕션
- [ ] iOS는 2차: Apple 개발자 $99/년, Mac이 없으면 Codemagic 같은 클라우드 빌드 사용

### Phase 4 – 출시 후 (지속)
- [ ] 지표 보기: D1/D7 리텐션, 사용자당 판별 수, 구독 전환율, 판별당 비용
- [ ] 피드백 기반 프롬프트 개선, 자주 틀리는 품목은 가이드 데이터로 보강
- [ ] 아파트 관리사무소·학교·지자체에 제안서 (사용자 수 + 정확도 데이터 첨부)
- [ ] 환경·공공데이터 관련 공모전 응모 (포트폴리오 + 상금 + 홍보)

## 4. 비용 감각

- Gemini 2.5 Flash 이미지 판별: 1회당 몇 원 수준. 월 1만 회면 수만 원대. 무료 횟수 제한이 있으면 감당 가능
- Firebase: 무료 등급으로 시작 가능 (Firestore·Auth·Analytics)
- 고정비: Play $25(1회), Apple $99/년(iOS 할 때), RevenueCat 무료 등급(월 $2.5k 매출까지)

## 5. 기술 부채 / 지금 알고 있는 한계

- 설정 화면의 API 키 입력은 Phase 1에서 제거 (개발자용 숨김 메뉴로만 남김)
- 기록은 SharedPreferences → 항목이 늘면 sqflite/Isar로 이전
- 가이드 데이터는 앱 내장 → 원격 설정(Remote Config)으로 바꾸면 앱 업데이트 없이 수정 가능
- 지자체마다 기준이 달라 "참고용" 문구는 유지해야 함 (법적 리스크 완화)
